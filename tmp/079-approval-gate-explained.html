079 · Agent Approval Gate, explained

A "please confirm" popup for an AI agent. The hard part is not the popup, it is sending the answer exactly once while the clock runs and the connection flickers. Each section below says what the problem is in plain words, then shows the exact lines of solution.tsx that handle it.

The request object looks like this: an id, a one-line action, the current text, the proposed text, and expiresAt in epoch milliseconds. Your component gets it as a prop, or null when there is nothing to approve.

4. The requirements, one by one, with the code that satisfies them

Display

Show the request as a readable diff

Split both texts on newlines. A line only in the current text is removed, only in the proposed text is added, in both is the same. No clever diff algorithm, set membership is enough.

Without it: the reviewer reads two walls of text and misses the one changed line.
/** Set-membership diff: current lines in order, then lines only in proposed. */
export function computeDiff(current: string, proposed: string): DiffLine[] {
  const before = current.split('\n');
  const after = proposed.split('\n');
  const afterSet = new Set(after);
  const beforeSet = new Set(before);
  return [
    ...before.map<DiffLine>((text) => ({ text, change: afterSet.has(text) ? 'same' : 'removed' })),
    ...after.filter((text) => !beforeSet.has(text)).map<DiffLine>((text) => ({ text, change: 'added' })),
  ];
}
Reconnect

Reset on a new request, keep state on a replay

The stream can drop and replay the same request. Your component then receives a new object with the same id. The solution does not track that with effects at all: it gives the inner dialog a React key equal to the request id. Same id, same key, React keeps the component and its pending or sent state. Different id, different key, React throws the old one away and mounts a fresh one.

Without it: after a reconnect the buttons come back to life and the user approves a second time.

This is the single most important line in the file. Everything about "did the id change" is handled by React, and the old instance's late promise lands in a component that no longer exists.

/**
 * The outer component only picks the identity: a different request id mounts
 * a fresh Gate (full reset), the same id keeps the existing one (pending/sent
 * state survives a replayed event), null renders nothing.
 */
export function ApprovalGate({ request, onDecide }: ApprovalGateProps): ReactElement | null {
  if (!request) return null;
  return <Gate key={request.id} request={request} onDecide={onDecide} />;
}
State

Track four things, no more

The phase (idle, pending, sent), an error message, whether the user opened the editor and what they typed, and the current time for the countdown. The time is state so the component re-renders every second.

Without it: you end up with booleans like isLoading and isSent that can both be true.
  const [phase, setPhase] = useState<Phase>('idle');
  const [error, setError] = useState<string | null>(null);
  const [editing, setEditing] = useState(false);
  const [draft, setDraft] = useState(request.proposed);
  const [now, setNow] = useState(() => Date.now());
Exactly once

Send exactly once

When the user clicks, React will disable the buttons, but only after it re-renders. A double-click's second event can arrive before that. So the first check is a ref, which flips synchronously, and then the state follows. The alive ref stops a late server response from touching a component that was unmounted or replaced.

Without it: two approvals reach the server from one double-click.
  // Synchronous guard: state lags a tick, a ref does not. Double-clicks hit this.
  const inFlightRef = useRef(false);
  // Unmount (or a different-id remount) must make a late settlement a no-op.
  const aliveRef = useRef(true);
  useEffect(() => {
    aliveRef.current = true;
    return () => {
      aliveRef.current = false;
    };
  }, []);
Clock

Count down, but only while idle

A one-second interval updates the time. Remaining seconds are computed from expiresAt, never stored. "Expired" is true only when the clock is at zero and nothing was sent. If a decision is in flight when the deadline passes, the server is the one deciding now, so the dialog waits for the answer instead of showing Expired.

Without it: a user who clicked at 4.9 seconds sees Expired while their approval is actually being processed.
  useEffect(() => {
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(id);
  }, []);

  const remaining = Math.max(0, Math.ceil((request.expiresAt - now) / 1000));
  // Expiry only matters while a decision has not been started: a decision in
  // flight across the deadline is the server's to accept or refuse.
  const expired = remaining === 0 && phase === 'idle';
  const locked = phase !== 'idle' || expired;
Core

The decision function

One function for all three outcomes. Guard first, mark in flight, flip to pending, call onDecide. On resolve, mark sent. On reject, clear the in-flight ref, go back to idle, show the error, and let the user retry. Approve picks between plain approve and approve_edited based on whether the editor is open.

Without it: the three buttons each grow their own copy of the guard logic and drift apart.
  const decide = (decision: ApprovalDecision) => {
    if (inFlightRef.current || locked) return;
    inFlightRef.current = true;
    setPhase('pending');
    setError(null);
    onDecide(decision).then(
      () => {
        if (aliveRef.current) setPhase('sent');
      },
      (err: unknown) => {
        inFlightRef.current = false;
        if (!aliveRef.current) return;
        setPhase('idle');
        setError(err instanceof Error ? err.message : String(err));
      },
    );
  };
Handlers

Wire the buttons

Approve and Reject are thin wrappers around decide. Edit only opens the textarea; Approve afterwards sends the edited text. Reject while editing still sends a plain reject, because rejecting an edited proposal makes no sense.

  const approve = () =>
    decide(
      editing
        ? { requestId: request.id, kind: 'approve_edited', proposed: draft }
        : { requestId: request.id, kind: 'approve' },
    );
  const reject = () => decide({ requestId: request.id, kind: 'reject' });
Render

Render from derived values

Everything on screen is computed from the four pieces of state. Locked disables all buttons when the phase is not idle or the request expired. The status line shows one of three strings, and the alert shows Expired or the error. Nothing is stored twice.

5. How a click flows through the code

click Approve
→
approve()
editing? approve_edited : approve
→
decide()
inFlightRef? locked? → return
→
inFlightRef = true
setPhase('pending')
→
onDecide(decision)
↳ resolve →
aliveRef? setPhase('sent')
· reject →
inFlightRef = false, setPhase('idle'), setError(msg)

Meanwhile the interval keeps updating now. Because expired requires phase === 'idle', the clock reaching zero during pending changes nothing on screen.

6. What to say in the interview

  • State shape first: "a three-value phase plus an error string, with editor state and the clock kept separate."
  • Name the hazard: "double submission and reconnect replay are the two races; a ref guards the first, a React key handles the second."
  • Qualifying question: "when the deadline passes with a decision in flight, who wins, client or server?" Then state the assumption: the server.
  • First test: "double-click Approve calls onDecide exactly once."
  • Trade-off to volunteer: keying by id resets everything on a new request, including an unsent edit. For an approval dialog that is correct; for a long form it would not be.
Full solution.tsx
import { useEffect, useId, useRef, useState, type ReactElement } from 'react';

export interface ApprovalRequest {
  id: string;
  action: string;
  proposed: string;
  current: string;
  expiresAt: number;
}

export type ApprovalDecision =
  | { requestId: string; kind: 'approve' | 'reject' }
  | { requestId: string; kind: 'approve_edited'; proposed: string };

export type DiffChange = 'added' | 'removed' | 'same';

export interface DiffLine {
  text: string;
  change: DiffChange;
}

export interface ApprovalGateProps {
  request: ApprovalRequest | null;
  onDecide: (decision: ApprovalDecision) => Promise<void>;
}

/** Set-membership diff: current lines in order, then lines only in proposed. */
export function computeDiff(current: string, proposed: string): DiffLine[] {
  const before = current.split('\n');
  const after = proposed.split('\n');
  const afterSet = new Set(after);
  const beforeSet = new Set(before);
  return [
    ...before.map<DiffLine>((text) => ({ text, change: afterSet.has(text) ? 'same' : 'removed' })),
    ...after.filter((text) => !beforeSet.has(text)).map<DiffLine>((text) => ({ text, change: 'added' })),
  ];
}

/**
 * The outer component only picks the identity: a different request id mounts
 * a fresh Gate (full reset), the same id keeps the existing one (pending/sent
 * state survives a replayed event), null renders nothing.
 */
export function ApprovalGate({ request, onDecide }: ApprovalGateProps): ReactElement | null {
  if (!request) return null;
  return <Gate key={request.id} request={request} onDecide={onDecide} />;
}

type Phase = 'idle' | 'pending' | 'sent';

function Gate({ request, onDecide }: { request: ApprovalRequest; onDecide: ApprovalGateProps['onDecide'] }): ReactElement {
  const titleId = useId();
  const editorId = useId();

  const [phase, setPhase] = useState<Phase>('idle');
  const [error, setError] = useState<string | null>(null);
  const [editing, setEditing] = useState(false);
  const [draft, setDraft] = useState(request.proposed);
  const [now, setNow] = useState(() => Date.now());

  // Synchronous guard: state lags a tick, a ref does not. Double-clicks hit this.
  const inFlightRef = useRef(false);
  // Unmount (or a different-id remount) must make a late settlement a no-op.
  const aliveRef = useRef(true);
  useEffect(() => {
    aliveRef.current = true;
    return () => {
      aliveRef.current = false;
    };
  }, []);

  useEffect(() => {
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(id);
  }, []);

  const remaining = Math.max(0, Math.ceil((request.expiresAt - now) / 1000));
  // Expiry only matters while a decision has not been started: a decision in
  // flight across the deadline is the server's to accept or refuse.
  const expired = remaining === 0 && phase === 'idle';
  const locked = phase !== 'idle' || expired;

  const decide = (decision: ApprovalDecision) => {
    if (inFlightRef.current || locked) return;
    inFlightRef.current = true;
    setPhase('pending');
    setError(null);
    onDecide(decision).then(
      () => {
        if (aliveRef.current) setPhase('sent');
      },
      (err: unknown) => {
        inFlightRef.current = false;
        if (!aliveRef.current) return;
        setPhase('idle');
        setError(err instanceof Error ? err.message : String(err));
      },
    );
  };

  const approve = () =>
    decide(
      editing
        ? { requestId: request.id, kind: 'approve_edited', proposed: draft }
        : { requestId: request.id, kind: 'approve' },
    );
  const reject = () => decide({ requestId: request.id, kind: 'reject' });

  return (
    <div role="dialog" aria-labelledby={titleId} aria-busy={phase === 'pending' || undefined}>
      <h2 id={titleId}>Approval required</h2>
      <p>{request.action}</p>

      <ul aria-label="Diff">
        {computeDiff(request.current, request.proposed).map((line, i) => (
          <li key={i} data-change={line.change}>
            {line.text}
          </li>
        ))}
      </ul>

      {editing && (
        <div>
          <label htmlFor={editorId}>Proposed action</label>
          <textarea id={editorId} value={draft} onChange={(e) => setDraft(e.target.value)} disabled={locked} />
        </div>
      )}

      <div>
        <button type="button" onClick={approve} disabled={locked}>
          Approve
        </button>
        <button type="button" onClick={reject} disabled={locked}>
          Reject
        </button>
        <button type="button" onClick={() => setEditing(true)} disabled={locked}>
          Edit
        </button>
      </div>

      <div role="status">
        {phase === 'sent' ? 'Decision sent' : phase === 'pending' ? 'Sending…' : expired ? '' : `Expires in ${remaining}s`}
      </div>
      {expired && <div role="alert">Expired</div>}
      {error !== null && <div role="alert">{error}</div>}
    </div>
  );
}
